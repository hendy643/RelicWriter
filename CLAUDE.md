# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Build: `dotnet build RelicWriter.slnx`
- Run: `dotnet run --project RelicWriter.Desktop`
- Regenerate codecs from the spec: `dotnet run --project RelicWriter.Generator -- docs/save-spec.xml RelicWriter.Common/Codecs/Generated`
- Update the spec for a game build: `dotnet run --project RelicWriter.Extractor -- --game <game dir> --saves <saves dir> --previous docs/save-spec.xml --out <dir>`
- New game data migration: `dotnet run --project RelicWriter.Extractor -- gamedata --game <game dir> --out Database --saves <saves dir>` (`--game-version <x.y>` on Linux), then rebuild (see `docs/game-database.md`)
- Windows (one self-contained single-file trimmed ReadyToRun exe without pdbs, no installer): `packaging/windows/build.sh`, see `docs/windows.md`
- Flatpak (Linux, self-contained linux-x64 trimmed ReadyToRun): `packaging/flatpak/build.sh`, see `docs/flatpak.md`
- Icons: `RelicWriter/Assets/Icon.svg` is the master; `powershell -File packaging/icons/make-icons.ps1` (needs Chrome or Edge) or `packaging/icons/make-icons.sh` (Chrome, Chromium, Edge or rsvg-convert, and python3) renders `Icon.ico`, `Icon.png` and the Linux sizes in `packaging/flatpak/icons/` from it
- CI and releases: `master` is protected by rulesets (pull requests only, the Build checks must pass, only the owner and maintainers merge); `.github/workflows/build.yml` checks pull requests and `release.yml` (starts when a pull request that changes the version in `version.json` is merged, e.g. from `release/1.0.0` prepared with `packaging/bump-version.ps1` or `.sh`, or all of it with `packaging/release.ps1 <version>` or `.sh`; owner and maintainers only) publishes the MSI, Flatpak and `version.json`; see `docs/releasing.md`
- Tests: `dotnet test RelicWriter.Tests`. No linting is set up.

## Architecture

Avalonia 12 / .NET 10 desktop app (Windows and Linux only; Android, iOS and Browser heads were intentionally removed, so don't reintroduce single-view lifetime code).

- `RelicWriter/` — shared UI library: `App.axaml(.cs)`, `Themes/Cyberpunk.axaml` (brushes + style classes), `Views/`, `ViewModels/` (CommunityToolkit.Mvvm), `Assets/` (embedded as `AvaloniaResource`). References `RelicWriter.Common`. `MainView` hosts a TabControl (Character, Perks, Appearance, Inventory, Vehicles, Save Info, Nodes); each tab is a `ContentControl` bound to a view model and resolved by `ViewLocator`. Compiled bindings are off by default (classic `{Binding}`). Edit limits (level, attributes 3-20, skills, text `MaxLength`) live in the view models (`GameEdition` for the game ones) and are bound as Minimum/Maximum in the XAML. Pass a `sav.dat` path as the first argument to open it at startup. The UI never shows ids: item and vehicle names come from `RecordNames` in `RelicWriter.Common`: the in-game name from the game database (`GameDatabase`, below), else a readable form of the record name. The Inventory tab can add items: `Inventory.Add` copies the plainest item of the same `ItemShape` in the save into V's bag (the sub-inventory count, the item id header and the node numbering are kept in step; checked by re-reading 100 real saves, not by loading in the game), from the `item` table of the game database (`ItemSearch`: case-insensitive fuzzy search plus category, type and quality filters; expansion items only with Phantom Liberty on). The Perks tab sets the level of every perk (`Model/Perks`, list and costs in the game database, see `docs/game-data.md`) and keeps the unspent perk and Relic points in step. The Appearance tab edits the face-shape presets (eyes, nose, mouth, jaw) of the `CharacetrCustomization_Appearances` node (`Model/Appearance`, refused unless the node re-encodes byte for byte) and lists the creator's parts read-only; it has no 3D preview and cannot change skin, hair or makeup yet, because the valid options live in the game's files. Edit limits and features follow the game patch of the save (`GameEdition` in `RelicWriter.Common/Model`, `docs/game-versions.md`): level cap, the skills shown, the Perks tab and the Relic tree; Save Info shows the patch, a Phantom Liberty checkbox (not stored in the save), and moves the save to a later patch with the same save version. `GameLocator` finds the install from launcher configs (Steam manifests, GOG registry, Epic manifests, Lutris, Heroic). Vehicle tile pictures are not stored: the game database gives the atlas and part, and `GameIcons` (`RelicWriter.GameAssets`) cuts the picture out of the player's own install; the GAME FOLDER button picks the install if `GameLocator` can't find it. The database holds CD PROJEKT RED's text; check redistribution before publishing a build.
- `RelicWriter.Common/` — save game library in three layers (no UI dependencies). The format is specified in `docs/save-spec.xml` (source of truth, edited by hand and updated by the Extractor) with prose in the other `docs/*.md`.
  - `Container/` (namespace `RelicWriter.Common.Container`): `SaveFile` (`SaveHeader` + tree of raw `SaveNode`s), `SaveReader`/`SaveWriter` (LZ4 chunks, node table). Version-independent and lossless: unknown nodes round-trip, including `SaveNode.Trailing` (data after the last child) and `SaveNode.After` (gap bytes between siblings).
  - `Codecs/`: `INodeCodec<T>`, one file per codec; version gates go inside the codec using `SaveContext.SaveVersion`. Only a few exist so far; nodes without a codec stay raw.
  - `Model/`: `SaveGame` (one shape for all versions, what the UI binds to): `Load(SaveFile)` / `ApplyTo(SaveFile)` go through the codecs. `NodeAvailability` (in `Container/`) is a read-only table of which nodes appear in which save versions (observed versions 193, 224, 254, 261, 263, 269, 277 only).
- `RelicWriter.Common/GameData/` — the game database: `GameDatabase` (in-memory snapshot: enum defaults, record names, vehicles, perks; `GameDatabase.Current`), `Storage/` (EF Core `GameDbContext`, the schema migration, and one migration class per data update). The data lives in `gamedata.db` in the user's local data folder, migrated on start; data migrations are the SQL scripts in `Database/` (embedded), only ever added. Backwards compatible, refuses a file migrated by a newer app. See `docs/game-database.md`. `GameLocator` also lives here.
- `RelicWriter.GameAssets/` — reads the game's own files (archives, TweakDB, CR2W, on-screen text, `GameIcons`); used by the Extractor, `Model3D` and the vehicle pictures. Archive data is decompressed with the managed `Kraken` decoder on every system (`docs/kraken.md`; checked against the game's Oodle DLL on 360 real segments and the vehicle atlas); the DLL is not loaded.
- `RelicWriter.Model3D/` — library for the character preview (work in progress; depends on `RelicWriter.Common`, no UI dependency, so its decoders and the software renderer can be tested without Avalonia). `Resources/RedFile` reads any game resource file (CR2W) into plain values. Planned on top of it: appearance and entity files, meshes, materials, textures. Rendering is done on the GPU with Avalonia's `OpenGlControlBase` (GLES 3 via ANGLE on Windows, EGL/GLX on Linux; Avalonia has no Vulkan control), in a separate Avalonia-facing project so this library stays free of UI and GL code. Reads the player's own game files only; nothing from the game is bundled.
- `RelicWriter.Generator/` — console tool: reads `docs/save-spec.xml` (the complete record of the save format) and writes one record + `INodeCodec` per supported node into `RelicWriter.Common/Codecs/Generated/*.g.cs` (committed; never edit by hand). It prints the nodes it skips and why (system blobs, `group`/`switch`/`repeat`/`parallelArrays` layouts and data after children are not emitted yet).
- `RelicWriter.Extractor/` — console tool. `gamedata` writes the next game database migration (see `docs/game-database.md`). Otherwise reads a game install and saves and writes `<out>/<game build>/save-spec.xml`: the previous spec updated with the game build (exe product version), observed save versions, node first/last seen and whether each node name is a string in the exe. It does not extract layouts (those come from reading the game's loaders in Ghidra); nodes it has not seen before are added with `status="open"`.
- `RelicWriter.Tests/` — xunit, no outside files: `Fixtures/SyntheticSave` builds saves in memory for save versions 193 to 277 (character blob, inventory with item gaps, garage, Relic perks), and the game-data tests build a small TweakDB in a temp folder. Hand-written payloads cover the generated codecs. Nothing reads real saves or the game install. Run with `dotnet test RelicWriter.Tests`.
- `RelicWriter.Desktop/` — thin `WinExe` entry point (`Program.cs`) that references `RelicWriter` and starts the classic desktop lifetime. `App.OnFrameworkInitializationCompleted` creates `MainWindow` with a `MainViewModel`.
- `ViewLocator` maps a `*ViewModel` type to the `*View` type of the same name by string replacement on the full type name, so view and view model names and namespaces must mirror each other.
- Versions are only edited in `version.json` (root: app, per-project components, and `database` = the save version the data was built for); the `SyncVersion` task in `Directory.Build.targets` writes them into the project files and manifests before every build. `Common/AppInfo/AppVersion` gives the version the About tab and header show (see `docs/versions.md`); there is no self-updater.
- NuGet versions are centralized in `Directory.Packages.props`; keep all Avalonia packages on the same version.
- `AvaloniaUI.DiagnosticsSupport` and `AttachDeveloperTools()` are Debug-only.
